# DESIGN.md — Editorial Design Specification

A single-column technical book in the O'Reilly tradition: 7 × 9 trim, one justified
column, strong heading hierarchy, chapter-level anatomy, and restrained color. Values
companions: `FONTS.md` (typography) and `COLOR.md` (palette). Usage guidance ("how to
write") lives in `manuscript/_STYLE.md`.

| File | Contents |
| --- | --- |
| `DESIGN.md` | This file: layout, structure, numbering, callouts, footnotes, visuals |
| `FONTS.md` | Families, files, weights, type-scale values, fallbacks |
| `COLOR.md` | Color tokens and diagram palette values |
| `css/` | Implementation: `tokens.css`, `book.css`, `print.css`, `epub.css`, `site.css` |
| `fonts/` | Font binaries (generated by `bun run prepare`; see `fonts/README.md`) |

The print pipeline (Paged.js) and the website share one design: **a single column**,
the same type hierarchy, and the same tokens. The website adds a sidebar and
interactive artifacts; it never reflows the text into two columns.

## 1. Page geometry

- **Trim size:** 7 × 9 in (504 × 648 pt).
- **Margins:** inside (gutter) 0.875 in, outside 0.625 in, top 0.75 in, bottom 1.0 in.
- Declared in exactly three places; if the trim size changes, update all three:
  1. `book.config.ts` → `page.width` / `page.height`
  2. `design/css/print.css` → `@page { size: 7in 9in; }`
  3. `design/css/tokens.css` → `--page-width` / `--page-height`

The PDF build post-processes every page with `pdf-lib` to force MediaBox, CropBox,
BleedBox, TrimBox, and ArtBox to exactly 504 × 648 pt (Chromium rounds fractional
inch sizes).

## 2. The single column

- **One justified column**, hyphenated, with clean paragraph spacing. There is no
  second column and no column-span machinery.
- Measure: about 68–75 characters at 10 pt. The website uses the same measure
  (`--measure: 68ch`).
- Figures, tables, code blocks, and display equations all use the full text measure.
- `::: wide` and `::: wide page` remain accepted for compatibility, but they have no
  layout effect in a single-column book; do not reach for them.
- Keep a figure near its first reference. If a figure lands a page away from the
  paragraph that discusses it, move the figure, not the text.

## 3. Running heads

- **Verso (left page):** page number at the outer edge, book title on the right.
- **Recto (right page):** chapter title on the left, page number at the outer edge.
- Type: Barlow Condensed, 8–8.5 pt, `--ink-muted`, small caps or uppercase.
- Mechanism: `string-set: chapter-title attr(data-running-title)`; frontmatter
  `runningTitle` overrides a long visible title.
- Suppressed on the cover, part-title pages, and the TOC. **No page number at the
  bottom of the page.**

## 4. Chapter anatomy

Every chapter follows the same arc:

1. **Chapter opener** — `CHAPTER N` label, title, and an optional epigraph
   (frontmatter `epigraph` + `epigraphAttribution`, set in Minion Pro italic, 9–9.5 pt,
   with an em-dash attribution).
2. **Framing and roadmap** — 2–4 paragraphs on why the topic matters, then a short
   roadmap of the chapter's sections.
3. **Core sections** — A/B/C headings (`##`, `###`, `####`).
4. **Chapter summary** — a one-page narrative synthesis of the trade-offs.
5. **References** — numbered `[1]`, `[2]` at the chapter end, or a `kind: references`
   back-matter chapter for book-wide lists.

Front matter order: cover, title page, copyright, table of contents, preface.

- A **part** opens on a new page with a large Roman numeral and the part title.
- A **chapter** opens on a new page.
- **Back matter:** `kind: references` — single-column, unnumbered, in the TOC.

## 5. Table of contents

- Part names: uppercase, muted gray labels.
- Entries: chapter number, title, dotted leader, page number.
- References entries have no chapter number.
- Page numbers via Paged.js `target-counter`; hidden on screen and on the website
  (the sidebar is the site's TOC).

## 6. Numbering

- **Sections:** `##` numbered 1, 2, 3 … per chapter; `###` and deeper unnumbered.
- **Display equations:** (1), (2), … per chapter, number flush right.
- **Figures and tables:** `Figure 1-1`, `Table 1-2` — chapter, hyphen, sequence.
- **Examples:** `Example 1-1` for formal listings; short snippets stay inline and
  uncaptioned.
- **Notes (footnotes):** 1, 2, 3 … per chapter (§8).
- **References:** `[1]`, `[2]` … per chapter.
- **Artifacts (website):** numbered like figures; pinpoint ids per
  `ARCHITECTURE.md` §9.

Numbers are generated by the build; never typed by the writer.

## 7. Callouts (the seven note types)

How notes render in every output (PDF, website, EPUB). Usage discipline — when to use
a callout and when not to — is `manuscript/_STYLE.md` §6.

### 7.1 Rendering model

Notes are part of the running text, not decoration:

- **Run-in bold label**, then the body. Example: **Theorem.** *Every range sum can be
  answered in constant time.*
- **No box, no background, no border, no icon.** Separation from body text comes from
  the label and spacing alone.
- The label is generated by the build from the note type; the writer never types it.
- A custom title may follow the note name: `::: definition Prefix sums`.
- Notes flow inside the measure; they do not float or span.

### 7.2 The seven types

| Type | Purpose | Body style |
| --- | --- | --- |
| `definition` | Introduce a term or formal object | Italic |
| `theorem` | State a claim that is proved or justified | Italic |
| `example` | Work a concrete case (also used for exercises) | Upright |
| `note` | Context that is useful but not essential | Upright |
| `tip` | Practical advice, shortcut, contest habit | Upright |
| `warning` | A pitfall that costs WA / RE / TLE | Upright |
| `complexity` | Time and memory costs of the thing just built | Upright |

Constraints:

- No emphasis markup inside theorem and definition bodies (the body is already
  italic).
- No nesting of notes; no display math or code blocks inside a note.
- Syntax:

  ```md
  ::: definition Prefix sums
  The prefix-sum array of $a$ is the array $p$ with $p_i = a_0 + \dots + a_i$.
  :::
  ```

### 7.3 Reserved colors

Callouts have no background by default. The semantic tokens in `COLOR.md` exist only
for the rare case color supports the label:

| Token | Value | Reserved for |
| --- | --- | --- |
| `--warning` / `--warning-soft` | `#7a4a00` / `#f7f1e6` | `tip`, `warning` |
| `--danger` / `--danger-soft` | `#8a1f1f` / `#f8eded` | `warning` (hard constraint) |
| `--note` / `--note-soft` | `#333333` / `#f3f3f3` | `note` |

A color never replaces the label; grayscale output must lose nothing.

### 7.4 LaTeX target

Each note type maps to a matching LaTeX environment with run-in label styling:
`\begin{definition}[Title] … \end{definition}` etc. (conversion contract:
`AGENTS.md` §2).

## 8. Footnotes and citations

How footnotes and citations work in every output. Usage guidance is
`manuscript/_STYLE.md` §11.

### 8.1 Placement

Notes are set at the **bottom of the page**, not at the end of the chapter:

- Source is a normal Markdown footnote: `Text.[^label]` and `[^label]: The note.`
- The build copies each note to its call site; Paged.js floats it to the `@footnote`
  area with `float: footnote`.
- Numbering restarts at 1 in each chapter; the writer never types note numbers.
- A hairline (`--rule`) separates notes from body text.

### 8.2 Values

| Element | Family | Size / leading | Alignment |
| --- | --- | --- | --- |
| Footnote text | Minion Pro Regular | 7.5 pt / 10 pt | Left, ragged right |
| Footnote marker | Minion Pro | superscript, body size | in text |
| Separator | — | hairline `--rule` | full measure |

### 8.3 Per-output behavior

| Output | Behavior |
| --- | --- |
| PDF / print | Page bottom via Paged.js `@footnote` float |
| HTML / website | End-of-chapter note list remains for screen readers; hidden in print |
| EPUB | Converted to endnotes (`epub:type="endnotes"` / `epub:type="endnote"`) |

### 8.4 Citations

- Short asides, attributions, and citations ride in footnotes.
- Full reference lists live in a `kind: references` chapter
  (e.g. `manuscript/99-references/`): single-column, unnumbered sections, included in
  the table of contents, no chapter number in the TOC entry.
- Reference entries are numbered `[1]`, `[2]` … and may carry `doi` or archival links;
  link rot is a design failure, so prefer stable or archived URLs.
- No citation style is invented inside a chapter; the references chapter owns the
  list format, used consistently (numeric or author–year).
- Nothing essential goes in a footnote: if skipping it breaks the argument, it is
  body text.

## 9. Micro-elements

| Element | Syntax | Rendering |
| --- | --- | --- |
| **Sidebar** | `::: sidebar Title` … `:::` | Shaded, offset block with a bold title; used for tangents that would break the narrative |
| **Definition list** | `Term` / `: explanation` (deflist) | Bold term on its own line, indented explanation |
| **Comparison table** | normal Markdown table | Chapter-numbered caption, small-caps header row |
| **Numbered example** | `::: example Example 1-5. Title` with a code fence inside | `Example 1-5` label, then the listing |
| **Code listing** | fenced code with a language | JetBrains Mono, full measure, no caption unless numbered |

Sidebars and admonitions are different things: a sidebar is a structural tangent, an
admonition (`note`, `warning`, `tip`) is a short remark in the flow. Do not use a
sidebar for a sentence that could be a note.

## 10. Visuals

Interior diagrams are minimalist technical line art:

- Thin dark strokes on the page surface, light gray shading only to mark a state, a
  compressed block, or a modified row.
- A consistent vocabulary: **cylinders** for storage/databases, **rectangles** for
  services, schemas, and memory pages, **arrows** for dataflow and pointers,
  **timelines** flowing left to right (horizontal lifelines, thick diagonal arrows for
  network messages), simple human icons for users/operators.
- Reuse running examples across sections; evolve one diagram instead of drawing a new
  one for each idea.
- Color follows `COLOR.md` §3 (soft fills, dark strokes, grayscale-safe). Color is
  never the only distinction.
- Every figure has alt text and a caption; every diagram must survive a grayscale
  print.
